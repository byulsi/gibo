# 데이터 연결 측정 결과 (2026-10-19)

Gibo 0.2.0의 세 데이터 연결(OpenBB, OpenDART, KRX)을 실제 투자 분석 흐름으로 돌려
디스크 용량, 대화 공간(토큰), 기능 중복, 변환 정확도, 시작 시간, 메모리를 쟀다.
측정 뒤의 결정과 Gibo에 반영한 내용은 마지막 절에 있다.

## 측정 방법

- **시나리오:** 8단계 투자 분석 워크플로우(리스크, 성장성, 이익의 질, 거버넌스,
  밸류에이션, 전술, 요약, 복기) + 거시경제 점검. 63개 요청.
- **종목:** 삼성전자(005930), 대주전자재료(078600, 최근 6개월 CB·BW 공시 6건,
  수주·가동률이 있는 제조업)
- **기준 자료:** 2025 사업연도 사업보고서(2026-03 제출), 2026-06~10 시세·수급
- **설치:** Gibo 0.2.0 `mcp/setup.sh`로 설치한 플러그인 데이터 폴더
- **부품 사용 기록:** 파이썬 서버는 `PYTHONPROFILEIMPORTTIME`, Node 서버는 모듈
  해석 훅으로 실제로 불러온 부품을 기록
- **토큰:** 글자 수로 추정(ASCII 4자당 1토큰, 한글 등 1자당 1토큰). 실제 토큰과
  다를 수 있으나 비교에는 충분하다.

한계: 시나리오에서 쓰지 않은 기능이 필요로 하는 부품은 판단하지 못했다.

## 핵심 결과

1. **DART 사업보고서 마크다운 변환이 핵심 내용을 버린다.** korean-dart-mcp 0.10.1의
   변환기(`build/lib/dart-xml.js`)가 `<LIBRARY>` 태그를 이미지처럼 제거한다. DART
   사업보고서는 이 태그로 본문 장을 묶어서 "II. 사업의 내용"(사업 개요, 제품,
   원재료·생산설비·가동률, 매출·수주), 연결재무제표 본문·주석, 미상환 전환사채
   발행현황이 빠진다. 원본 제목 기준 삼성전자 156개 중 55개, 대주전자재료 175개 중
   68개가 사라졌다. `<LIBRARY>` 태그만 벗기고 같은 변환기에 넣으면 빠지는 제목이
   3개(띄어쓰기가 특이한 "목차")로 줄었다.
2. **응답 몇 개가 대화 공간을 넘친다.** OpenBB EIA 석유 현황 보고서 약 658만 토큰,
   KRX 외국인 순매수 상위 종목 약 13만, OpenBB 미국 CPI 분석표 약 5만 9천, 사업보고서
   원문 전체(제한 해제 시) 삼성전자 약 30만. Claude Code의 MCP 출력 한도(기본
   25,000토큰)를 크게 넘는다.
3. **사업보고서 원문 도구는 기본값으로 소리 없이 자른다.** `download_document`는 기본
   10만 자에서 자른다. 삼성전자는 앞부분 약 17%만 오고 응답에 잘림 경고가 없다.
4. **DART 설치의 91%가 쓰이지 않는다.** 638MB 중 시나리오가 쓴 것은 57MB. 나머지는
   첨부 파일 변환 라이브러리(kordoc)의 선택 부품, 특히 수식 그림 인식용 AI 실행기
   (onnxruntime 약 447MB)다. 게다가 DART 웹사이트(dart.fss.or.kr)가 이 환경의
   프로그램 접속을 막아 첨부 파일 기능 자체가 동작하지 않는다.
5. **OpenBB는 메모리가 크다.** 세션마다 약 1.0GB로 시작해 질문 몇 개 뒤 약 1.3GB.
6. **국내 시세는 OpenBB(야후)보다 KRX가 맞다.** 같은 93거래일 중 18일 종가가 달랐고,
   하루는 거래량이 KRX 2,705만 주, 야후 1,191주였다.

| 연결 | 현재 | 시나리오가 쓴 부품 | 안 쓴 부품 | 가벼운 설치 | 감소 |
|---|---|---|---|---|---|
| DART | 633MB | 57MB | 581MB | 110MB | -523MB |
| OpenBB | 799MB | 414MB | 273MB | 660MB (최종 456MB) | -139MB (최종 -343MB) |
| KRX | 185MB | 135MB | 15MB | 그대로 | 0 |

- **DART 가벼운 설치:** `npm install --omit=optional`. 빠지는 것은 onnxruntime(node·web),
  @huggingface/transformers, sharp, @napi-rs/canvas, @hyzyla/pdfium. kordoc 본체와
  HWP 해석 부품(cfb, jszip)은 남는다.
- **OpenBB 가벼운 설치:** `openbb` 묶음 대신 데이터 출처 확장을 하나씩 설치하고
  `openbb-cli`, `openbb-devtools`를 뺀다. 빠지는 것은 ty, jedi, debugpy, virtualenv,
  ipython, pyzmq, pytest 등 개발 도구. 데이터 출처는 22개, 도구는 1,178개로 같다.
- **줄일 수 없는 것:** plotly·pywry(openbb-yfinance가 필수로 요구), statsmodels
  (openbb-technical 필수), pdfplumber(연준·나스닥 확장 필수), ruff(openbb-core 필수),
  scipy(변동성 계산에서 실제로 쓰임), matplotlib(pykrx가 불러옴).
- **동작 비교:** 가벼운 설치로 63개 요청과 기술적 계산 6종을 다시 돌려 결과가 모두
  같았다. 시작 시간과 메모리는 거의 같다(안 쓰던 부품이 빠졌기 때문).

### OpenBB 도구 검색 비용

OpenBB는 1,178개 도구를 숨기고 `search_tools`로 찾는다. 검색 한 번의 응답이 평균 약
7,400토큰, CFTC 검색은 약 27,000토큰이다. 실제 데이터 응답보다 검색 비용이 더 큰
경우가 많다.

### 사업보고서 원문 읽는 방식

| 방식 | 삼성전자 | 대주전자재료 |

| A. 기본값 그대로 | 약 5만 6천 (앞 17%만, 잘림 경고 없음) | 약 5만 3천 (앞부분만) |
| A. 제한 해제, 현재 변환 | 약 30만 (핵심 장 누락) | 약 12만 7천 (핵심 장 누락) |

| B. 항목 도구 | 거버넌스·주주 항목만 가능. 사업의 내용·주석은 항목 도구가 없음 | 같음 |

C 방식은 보정된 원문 전체의 3~10%로 필요한 장을 읽는다. 원문이 Claude 대화를 거치지
않고 파일이 되려면 원문을 받아 저장하는 스크립트가 필요하다.

## 변환 정확도

- **표 숫자:** 사업보고서 마크다운의 연결 손익 표와 DART 재무 데이터를 비교했다.
  삼성전자 매출액·영업이익·당기순이익, 대주전자재료 매출액·영업이익이 모두 일치했다.
- **단위 주의:** 삼성전자 표는 백만 원, 대주전자재료 표는 천 원 단위다. 표 위의 단위
  표시를 함께 읽어야 한다.
- **누락:** 위 핵심 결과 1. 글자만 뽑는 `text` 형식에는 누락된 장의 내용이 있다.
- **첨부 파일(kordoc):** 61개 공시의 첨부는 모두 공시 본문의 PDF 사본이었고 HWP는
  없었다. DART 웹사이트가 프로그램 접속에 빈 응답을 돌려줘 PDF를 내려받지 못했고,
  이후에는 첨부 목록 조회도 실패했다. kordoc의 변환 정확도는 측정하지 못했다.

## 결정과 반영 (2026-10-19)

| 항목 | 결정 | 반영 |
|---|---|---|
| `<LIBRARY>` 누락 | Gibo 안에서 고친다 (korean-dart-mcp에 의존하지 않음) | `mcp/dart-markdown.mjs`: 태그를 벗긴 뒤 같은 변환기 사용 |
| 큰 응답 | 파일로 저장하고 요약과 경로만 돌려준다 | `mcp/relay.py`: 약 2만 토큰 초과 시 `자료/응답/`에 저장 |
| 사업보고서 읽기 | C 방식(파일 먼저) | dart에 `save_report` 추가, `자료/사업보고서/`에 저장하고 목차·줄 번호 반환 |
| 가벼운 설치 | 반영 | `mcp/setup.sh`: DART `--omit=optional`, OpenBB 개별 확장 설치 |
| OpenBB 메모리 | 평소에는 쓰지 않는다 | 첫 OpenBB 도구 호출 때 시작(`--lazy`). 도구 목록은 캐시로 응답 |
| 기술적 지표 | 직접 계산 | krx에 `technical_indicators` 추가. OpenBB technical·charting 확장 제거 |
| 첨부 기능 | 안내로 막는다 | dart 안내문에 `get_attachments` 쓰지 않음, `save_report` 사용을 명시 |

### 반영 후 확인

- **OpenBB 추가 경량화:** 기술적 분석을 직접 계산하기로 해 `openbb-technical`,
  `openbb-charting`을 뺐다. openbb-yfinance는 차트 위젯 때문에 두 확장을 필수로
  요구하지만, 해당 코드는 위젯 함수 안에서만 불러와서 의존성 없이 설치했다.
  799MB → 456MB. 도구는 1,178개 → 1,115개(technical 59개, tmx 차트 4개 제외).
  시나리오 요청 8개의 결과는 같았다(실시간 환율의 당일 값만 다름).
- **지표 계산 검증:** 같은 KRX 시세(93거래일)로 OpenBB technical과 비교했다.
  이동평균·MACD·볼린저 밴드는 일치, RSI 33.12 대 33.19, ATR 13,588 대 13,590.
  RSI·ATR 차이는 Wilder 평활의 시작값 차이로, 기본 조회 기간(400일)에서는 더 줄어든다.
- **지표 응답 크기:** 약 600토큰. 시세를 OpenBB에 보내 계산할 때(요청 1천~2천5백
  토큰 + 응답)보다 작고, 지표 여러 개를 한 번에 돌려준다.
- **OpenBB 늦게 시작:** 캐시가 있으면 연결 응답이 0.05초. 첫 도구 호출 때 약 20초.
